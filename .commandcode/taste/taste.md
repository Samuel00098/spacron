## Workflow & Collaboration

- Likes to benchmark their app against analogous/commercial products and selectively borrow proven features and patterns into their own build (e.g., asked what to borrow from a competitor's agentic dev environment) rather than building in isolation. Confidence: 0.6
- Prefers to receive analysis and recommendations before implementing changes; explicitly requested analysis and feedback reports prior to taking action on design decisions. Wants recommendations documented in a reviewable format "so I can look at it and see if it's something I would like to do." Confidence: 0.85
- Prefers collaborative involvement in creative and visual design work rather than having outputs generated unilaterally; wants to work together on generating visual assets. Confidence: 0.6
- Trusts the assistant's design expertise and is willing to defer final decisions to the assistant's judgment ("it is up to you") while still expressing initial preferences — e.g., stated a preference for theme-following UI then explicitly asked "in terms of user experience, what do you think is best?" before deciding. Confidence: 0.75
- Works with multiple AI agents/tools in their workflow and delegates specific tasks to them; requests comprehensive, self-contained prompts that can be handed off to other agents without additional context ("a full-on prompt that I can give to other agents"). Confidence: 0.75
- When presented with a prioritized fix/improvement plan, prefers to approve and implement the complete scope at once ("yes work on them all") rather than a subset or staged rollout. Confidence: 0.65
- Project workflow runs multiple coding agents in parallel (e.g., claude, codex), each in its own pane and worktree branch, producing independent diffs the user can watch and review separately. Confidence: 0.7
- At times prefers the assistant to implement work directly in-process rather than delegating to parallel coding agents — when offered delegation for a multi-workstream task, explicitly said "do it yourself." Delegation is a workflow option, not a default expectation. Confidence: 0.7

## Visual & Aesthetic Preferences

- Drawn to urban/cityscape imagery (e.g., Chicago-style skylines, cityscapes) as visual aesthetics for tools and application backgrounds. Confidence: 0.7
- Prefers 2K resolution (2560×1440) for generated image assets to ensure sharpness on larger screens. Confidence: 0.8
- Prefers WebP format over PNG for image assets. Confidence: 0.8
- For UI backgrounds (e.g., behind frosted-glass overlays), strongly prefers calm, atmospheric, even-toned visuals with painterly softness over photographic sharpness — "fine art print" not "stock photo." Avoids readable text, sharp foreground objects, harsh geometric lines, people, and vehicles. Confidence: 0.75
- Values even luminance across visual compositions — no bright hot spots or deep shadow pockets; backgrounds should be functional UI support layers, not attention-grabbing focal points. Confidence: 0.7
- For dark mode visuals, prefers restrained compositions where most of the frame is near-black with sparse, dim elements and minimal light sources; avoids dramatic/bright elements competing with darkness. Confidence: 0.7
- Prefers embedded agent/TUI panes to stay visually coherent with the host app; originally favored them following the app's light/dark theme, but once it became clear the theme is locked at process launch and cannot be re-themed live, concluded always-dark is the better call — a stale light pane in a dark app is a jarring mismatch with no non-destructive fix. Confidence: 0.7
- Values predictable, consistent behavior over fragile or half-realized features: rejects "follow the theme at launch" mechanisms that silently go stale after an on-the-fly theme switch, and dismisses workarounds (e.g., injecting theme commands into a live PTY) that would fight the user; a reliable default beats a feature that can't stay live. Confidence: 0.7
- Inclined toward minimal-scope changes: when a new feature is already handled by existing infrastructure (e.g., agent terminal rooms already flow through the stage/panelist machinery), prefers to leave existing UI surfaces untouched rather than add redundant updates — asks the assistant to confirm whether a change is genuinely needed before committing to it. Confidence: 0.4
- Prefers one unified official mark for entries that belong to the same product family (e.g., Codebuff and Freebuff share a single brand) so their tiles render identically — pointed both at one shared asset and removed the stale, divergent icon rather than maintaining near-duplicate files. Confidence: 0.7
