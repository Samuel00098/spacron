# Chat-mode voice & dictation ride the CLI seams

The bare-Alt voice gesture and the dictation capture are **global and single-owner** — never add a second listener in ChatModePanel or the gesture double-toggles.

- Alt tap lives in FloatingPromptBar, which stays mounted even when chat mode hides the bar (`.interaction-chat .workspace-overlays`). When `interactionMode === 'chat'` it increments `chatVoiceModeRequest` (interactionMode.ts) instead of starting the bar's own call; ChatModePanel consumes the counter and toggles its composer voice.
- `transcriptionTarget` (transcription-hotkey.ts) says where the one shared dictation is aimed (`chat` | `field` | `terminal`). The chat composer strip renders when it is not a terminal; the CLI `TranscriptionIndicator` pill hides when it is `chat`, so the two surfaces never both report. `publishTarget` is try/catch on purpose: the label is a nicety, the dictation is the job.
- The chat voice strip is `SpectrumVisualizer`; `RealtimeVoiceState` is a subset of `SpectrumPhase`, so the float's phase drops straight in.
- **F9 is also mode-routed** from AppShell's capture-phase handler: when `interactionMode === 'chat'` it calls `toggleChatModeTranscription()`, which force-focuses `.chat-mode-composer textarea` so the capture can never fall back to a hidden CLI terminal; CLI mode keeps `toggleTerminalTranscription()`. `transcriptionActive` (a separate store) goes true the moment a capture is committed — before the mic opens — so the composer strip lights up during the arming beat where `transcriptionState` is still 'idle'.
- **`launchVoiceMode` (Ctrl+Shift+M) is mode-routed too**, at the same AppShell switch: chat mode hands it to `requestChatVoiceMode()` (same path as the bare-Alt tap); CLI mode keeps `launchPromptBarVoiceMode()`. The bare-Alt tap itself already routes in FloatingPromptBar.
- The composer's voice glow reuses the bar's `voicePillAura` keyframes via `.chat-mode-composer.voice-active`; define the class, reference the existing keyframes.
- Chat voice streams each exchange into the thread as live rows (`appendVoiceThreadMessage`), and dedups against orchestrator turns: `runOrchestratorVoice` drops the echoed user row (`removeThreadMessage`, added to chatThreads.ts) and sets a one-shot flag that suppresses the spoken echo of the reply `sendChatMessage` already recorded. Thread voice rows use `type: 'user'` / `type: 'agent'` to match normal rendering.
